# 验证记录与已知风险

记录日期：2026-11-09。以下均为一次真实排障中的观察，不是持续监控结果。
未发布原始日志、设备名称、账号、学校名称、内网 IP 或本机绝对路径。

## 已验证 / 已观察

| 项目 | 证据边界 |
|---|---|
| 同设备热点与校园网差异 | 用户反馈热点可用、校园网原先不可用；不是所有校园网的结论 |
| 普通与拆分 TLS 对照 | 针对部分端点，普通握手超时；拆分后可校验证书并收到 HTTP 响应 |
| 辅助域名误拒绝 | 本地程序日志显示拒绝；补充精确白名单后相应 TLS/HTTP 测试通过 |
| g 系列信令/中继 | 原解析端点在测试中关闭 TLS；保留原域名，使用备用端点后证书与握手测试通过 |
| 本地服务 | 仅监听 `127.0.0.1:17899` |
| UU 初次恢复 | 用户表示“现在是可以了”；当时 UU 手动代理与 Clash 规则同时存在，不能据此断言两者都必要 |
| 停用 UU 手动 SOCKS5 的对照 | 保留 Clash 规则/系统代理/本地程序，停用 UU 手动代理并重启 UU 用户进程后，用户确认“可以连接” |
| 停用后的实际路径 | 观察到 Clash 连接本地 `17899`，该次检查中没有 UU 子进程直接连接此端口；Clash 连接详情确认 nrd API 命中本地出站 |
| 远控会话观察 | 界面显示存在远控会话；同时仍曾显示服务器连接提示，因此不把全部界面状态恢复作为已验证结论 |
| 其他服务回归 | 当时 ChatGPT 经原 Clash 路径返回 HTTP 200；不是 Codex 全功能回归 |

## 未验证 / 仍有风险

- 远程画面、键鼠操作、文件传输、声音、多屏与高码率。
- UDP/P2P、直连优先、延迟与带宽。本适配器没有实现这些协议。
- 早期 UU 手动代理启用时，日志中曾出现 DNS 53 和非 443 端口请求被拒绝。
  当前已停用应用内手动代理，不再默认把这类请求全交给受限适配器；
  这并不代表 DNS、P2P 和全部其他功能都已验证。
- 重启、休眠唤醒、长时间运行、网络切换、UU/Clash 升级。
- 备用端点长期有效性及同一域名在不同区域后端上的业务一致性。
- 实际网络中的识别方式、管理政策与过滤设备归属。
- 用户级代理与 UU 各个子进程之间的覆盖范围。

因此目前的结论是：

> 当前设备与网络下，UU 不需要启用应用内手动 SOCKS5；通过 Clash 分流仍可连接。
> 这不是“移除了 SOCKS5 协议”：Clash 到本地程序仍使用 SOCKS5。
> 仍有已知限制，不能声称全面修复、没有其他问题或其他网络也一定适用。

## 应用内代理停用对照（2026-11-09）

1. 备份 UU 原有的代理配置，仅在本机保存，不提交到仓库。
2. 在 UU 的网络设置中点击“停用”，确认按钮变为“启用”。
3. 保留本地程序、Clash 规则、系统代理和当时的非 UU 流量路由不变。
4. 重启 UU 用户进程，以免复用启用手动代理时建立的连接。
5. 观察实际 socket：由 Clash 接入本地程序，而非 UU 直接接入。
6. 用户确认仍可以连接，因此保持 UU 手动代理停用，不恢复多余设置。

这一结果修正了此前仅根据“UU 子进程直接连接本地端口”就建议保留手动代理的推断：
观察到一条路径在使用，不代表它不可替代。文档不再默认要求 UU 内填写代理。
对照期间已存在远控会话，后续涉及退出/重启的测试应先结束会话，避免打断操作。

## 排障过程中修正的实现问题

1. 白名单仅包含 nrd 域名，错误拒绝实际观察到的两个辅助域名。
2. IP 形式 CONNECT 原本全部被拒；发布版要求解析并验证获准的 SNI 后才连接上游。
3. 旧版进程重启时可能留下连接；本地部署已清理旧进程，流关闭增加超时。
   本发布版使用前台运行，不包含依赖原作者本机路径/PID 文件的管理脚本。

## 不同网络的配置差异

原始排障临时在 Clash 中使用“UU 规则在前，`MATCH,DIRECT` 在后”的配置，
以免在校园网使用订阅代理节点。其后的原有规则不再生效。
这不是通用安装方式，也不适用于个人网络仍需远端代理的应用。
发布的示例仅展示精确 UU 规则，不含这个全局兜底。
对照测试时实际保留的是 nrd 域名规则；没有为了停用 UU 手动代理而新增辅助域名规则。
代码仍保留此前验证过的两个辅助域名白名单，但当前示例不要求额外分流它们。
