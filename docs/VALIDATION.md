未发布原始日志、设备名称、账号、学校名称、内网 IP 或本机绝对路径。

## 未验证 / 仍有风险

- 远程画面、键鼠操作、文件传输、声音、多屏与高码率。
- UDP/P2P、直连优先、延迟与带宽。本适配器没有实现这些协议。
- 日志中曾出现 DNS 53 和非 443 端口请求被拒绝；不能证明无功能影响。
- 重启、休眠唤醒、长时间运行、网络切换、UU/Clash 升级。
- 备用端点长期有效性及同一域名在不同区域后端上的业务一致性。
- 实际网络中的识别方式、管理政策与过滤设备归属。
- 用户级代理与 UU 各个子进程之间的覆盖范围。

因此目前的结论是：

> 在本案例中，针对性修改后用户反馈恢复可用；仍有已知限制，不能声称全面修复或没有其他问题。

不要禁用校验或盲目替换为不可信地址。

## 排障过程中修正的实现问题

1. 白名单仅包含 nrd 域名，错误拒绝实际观察到的两个辅助域名。
2. IP 形式 CONNECT 原本全部被拒；发布版要求解析并验证获准的 SNI 后才连接上游。
3. 旧版进程重启时可能留下连接；本地部署已清理旧进程，流关闭增加超时。
   本发布版使用前台运行，不包含依赖原作者本机路径/PID 文件的管理脚本。

## 不同网络的配置差异

原始排障临时在 Clash 中使用“UU 规则在前，`MATCH,DIRECT` 在后”的配置，
以免在校园网使用订阅代理节点。其后的原有规则不再生效。
这不是通用安装方式，也不适用于个人网络仍需远端代理的应用。
发布的示例仅展示精确 UU 规则，不含这个全局兜底。
